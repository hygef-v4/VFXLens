# X: access and evidence

Discover an authorized X API/search tool before using it. Do not assume API keys,
authenticated browsing or commercial access. If none exists, search indexed public
`x.com` / `twitter.com` posts with the native web tool and open the original link
when accessible. Do not bypass login walls, paywalls, rate limits or robots/access
restrictions. An inaccessible original remains inaccessible even if a snippet exists.

For each useful post record the original URL, author, publication date, linked
repo/demo, and what was actually shown. Record views/likes/reposts/bookmarks only
when the exact value is visible or provided by an authorized API, with the
observation timestamp. These mutable figures are not a complete growth history.

Evidence classes:

- **Directly inspected:** original post/demo and visible metadata actually opened.
- **Indexed lead:** search result/snippet; useful to find source code, not proof
  that the full post or video was inspected.
- **Secondary reporting:** named article/site attributes attention to a post;
  cite the reporting and retain its limits.
- **Unavailable:** access failed or metrics/date could not be verified.

Reported attention can justify a `Reported Viral` tag with attribution. Use
`Verified Viral` only with adequate observed, windowed evidence and a stated
definition of meaningful attention. A dramatic video, a popular author, an
undated screenshot or total likes alone does not establish recent momentum.
Code and license still need primary-source inspection even when a post is popular.

In the final report separate X API availability, public-post access, indexed search
and metric verification; “X search available” must not collapse these different
capabilities. Continue with other public sources when X is unavailable.
